# PrintHub

Печать документов через Telegram Web App: человек загружает файл в телеграме,
задаёт параметры, оплачивает — и забирает распечатку у принтера.

Печатью занимается [PbReader](https://github.com/2202zhan/PbReader): он же
рисует предпросмотр на сервере и считает цену. Предпросмотр и печать проходят
через один и тот же расчёт размещения, поэтому картинка на экране показывает то,
что выйдет из принтера, а не то, как выглядит PDF.

## Что уже работает

Фазы 0 и 1 — основание и вход с файлами.

| | |
|---|---|
| Вход | по подписи телеграма (`initData`), с обменом на собственный токен сессии |
| Файлы | загрузка, список, скачивание, удаление; формат определяется по содержимому |
| Интерфейс | три вкладки — главная, мои файлы, профиль |

Впереди: параметры и предпросмотр, цена и заказ, оплата через Kaspi, агент у
принтера.

## Устройство

```
Telegram ──► PrintHub Server (FastAPI)
                 ├── PbReader     — предпросмотр и цена
                 ├── SQLite/Postgres
                 └── Kaspi        — отдельный сервис (фаза 4)
                          │
                   мини-ПК у принтера (фаза 5)
```

Сервер на Python не по привычке: PbReader нужно вызывать напрямую, в том же
процессе. Через HTTP к отдельному сервису это тоже возможно, но тогда теряется
единственное, ради чего PbReader писался, — что предпросмотр и печать считает
один и тот же код.

## Запуск на своей машине

Нужны Python 3.10+ и Node 22+.

PrintHub живёт подкаталогом в репозитории PbReader, поэтому сам PbReader —
на уровень выше, и клонировать его отдельно не нужно.

```bash
cd printhub
pip install ..                   # PbReader из соседнего каталога; в PyPI его нет
pip install -e ".[dev]"

cd frontend && npm install && npm run build && cd ..

cp .env.example .env             # заполните PRINTHUB_SECRET_KEY
PRINTHUB_DEV_LOGIN=1 python -m printhub.cli serve
```

Откройте <http://127.0.0.1:8000>. Проверить настройки, ничего не запуская:
`python -m printhub.cli check`.

Фронт можно держать отдельно, с горячей перезагрузкой — тогда два процесса:

```bash
python -m printhub.cli serve          # API на 8000
cd frontend && npm run dev            # интерфейс на 5173, /api идёт в 8000
```

### Вход без телеграма

`PRINTHUB_DEV_LOGIN=1` включает `POST /api/auth/dev` — вход в браузере без
подписи. Иначе разрабатывать можно было бы только с телефона и публичным
HTTPS-туннелем.

Это **вход кому угодно под любым номером**. Вместе с `PRINTHUB_ENV=prod` процесс
не запускается: забыть выключить такое при выкатке — вопрос времени, поэтому
отказ жёсткий, а не предупреждение в журнале.

### Проверка в настоящем телеграме

Телеграм открывает веб-апп только по HTTPS, поэтому локальный адрес нужно
вывести наружу туннелем:

```bash
cloudflared tunnel --url http://localhost:8000     # выдаст https://…trycloudflare.com
```

Затем:

```bash
export PRINTHUB_BOT_TOKEN=...            # из @BotFather
export PRINTHUB_WEBAPP_URL=https://…trycloudflare.com
python -m printhub.cli bot               # настроит кнопку меню и ответит на /start
```

## Про токен бота

Токен — это не только доступ к переписке. Из него выводится ключ, которым
телеграм подписывает данные запуска, и проверка этой подписи — единственное, что
подтверждает личность пользователя. Кто знает токен, тот войдёт под любым
пользователем и прочитает его файлы.

Поэтому: только в переменной окружения, никогда в коде и никогда в git. CI ищет
токены в файлах и валит сборку, если находит. Засветившийся токен отзывается
командой `/revoke` в @BotFather — старый после этого перестаёт работать.

## Тесты

```bash
python -m pytest -q
```

Проверяются прежде всего границы: подделанная подпись, чужой номер в данных
запуска, просроченная строка запуска, чужой файл, файл сверх предела, имя файла
с путём внутри, вход без телеграма на боевом сервере.

## Раскладка

Внутри `printhub/` репозитория PbReader:

```
printhub/
  config.py          настройки из окружения
  sessions.py        наши токены сессии
  models.py, db.py   таблицы и подключение
  storage.py         приём файла на диск
  telegram/
    initdata.py      проверка подписи телеграма
    bot.py           бот: кнопка, открывающая веб-апп
  api/app.py         HTTP
  web/               сюда собирается фронт (в git не хранится)
frontend/            исходники интерфейса, React + Vite
tests/
```
