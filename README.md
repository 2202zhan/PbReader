# PbReader

Печать PDF и **достоверный** предпросмотр для аппаратов PrintBox.

Библиотека сама растеризует PDF (PDFium) и сама отправляет растр на принтер
через Win32 GDI. Внешний просмотрщик не запускается вообще.

## Зачем

Раньше печать шла через чужие программы — SumatraPDF и Foxit Reader, — и это
упиралось в три вещи.

**Окно поверх интерфейса.** Foxit печатает тихо, поэтому его и выбрали. Но
тихий режим у него один на все случаи, и настроить в нём почти ничего нельзя.

**Параметры, которых нет.** Лоток, масштаб, ориентация задавались либо
строкой в командной строке SumatraPDF, либо записью в глобальные настройки
принтера перед запуском Foxit. Первое не работало на Canon, второе меняло
настройки принтера для всей системы и ломалось при двух заданиях подряд.

**Предпросмотр, который врал.** В окне «параметры» показывался рендер
PDF-страницы. Это картинка документа, а не листа: без полей принтера, без
масштаба, без поворота, без ч/б, без обрезки. Человек видел одно, из аппарата
выходило другое.

Здесь всё это решается одним ходом: **предпросмотр и печать считает один и тот
же модуль раскладки** (`pbreader/layout.py`). Превью — это не «похожая
картинка», а тот же расчёт, отрисованный при 96 dpi вместо 600.

## Что умеет

| | |
|---|---|
| Масштаб | 1:1, вписать, уменьшить-если-надо, заполнить, свой процент, авто |
| Ориентация | книжная, альбомная, авто (по документу) |
| Цвет | цветная, чёрно-белая — **видно в предпросмотре** |
| Копии | подбор по копиям или по листам |
| Лоток | список берётся у драйвера, не вбивается руками |
| Страницы | `1,3,5-8,12-` — открытые диапазоны и повторы |
| Дуплекс | по длинной или короткой стороне, с чистым оборотом где надо |
| Предпросмотр | PNG листа по HTTP: поля принтера, масштаб, поворот, ч/б, обрезка |
| Ход печати | задание отслеживается в очереди: печатается / напечатано / нет бумаги / замятие |
| Расход тонера | заполнение листа в процентах и цена задания в «обычных страницах» — до оплаты |
| Счётчик аппарата | сколько листов механизм отпечатал на самом деле — по SNMP |
| Бумага и тонер | остаток в каждом лотке и картридже, замятия — **до оплаты** |
| Защищённые PDF | пароль спрашивается в окне и принимается в API |
| Формы | заполненные поля AcroForm печатаются, а не остаются пустым бланком |

## Установка

### На аппарат — готовой программой

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Собирает `dist\PbReader-0.1.0-setup.exe` — обычный установщик: Program Files,
ярлык в «Пуск», удаление через «Программы и компоненты». Python на аппарате не
нужен, он внутри. Подробности и что проверить после установки — в
[`packaging/README.md`](packaging/README.md).

Внутри два файла рядом, с общими библиотеками:

| | |
|---|---|
| `PbReader.exe` | **без консоли** — двойной щелчок открывает окно. Чёрное окно консоли поверх интерфейса киоска недопустимо, поэтому вывод идёт в `%LOCALAPPDATA%\PbReader\pbreader.log` |
| `pbreader.exe` | **консольный** — его запускает основной проект и читает stdout |

Собирать нужно на Windows: PyInstaller кладёт в сборку интерпретатор той
системы, где его запустили.

### Из исходников

```bash
pip install -e .            # ядро: pypdfium2, pillow, requests
pip install -e ".[windows]" # на аппарате: + pywin32, comtypes
```

Python 3.10+. `pypdfium2` ставится готовым бинарником, компилятор не нужен.

Настройки — `pbreader.json` рядом с программой или переменные `PBREADER_*`:
рабочий каталог, принтер по умолчанию, адрес и порт сервиса, срок хранения
файлов (`work_file_ttl_hours`, по умолчанию сутки) и частота уборки
(`sweep_interval_minutes`). Уборка обязательна: аппарат работает месяцами, а
каждое задание оставляет на диске скачанный оригинал и результат конвертации.
Файлы открытых сессий она не трогает.

> **Лицензии.** PDFium — BSD/Apache. MuPDF (PyMuPDF), который напрашивается
> первым, распространяется под AGPL: для коммерческих аппаратов это означает
> либо раскрытие своего кода, либо платную лицензию. Поэтому PDFium.

## Как пользоваться

### Как отдельная программа

```bash
pbreader ui
```

Открывается окно: слева параметры, справа лист. Документ кладётся перетаскиванием.
Всё работает без основного проекта — и даже без принтера: предпросмотр считается
всегда, просто поля берутся типовые и помечаются значком `≈`.

Окно — это HTML-страница, которую отдаёт тот же сервис. Отдельный движок
интерфейса ради этого не заводился: предпросмотр уже отдаётся картинкой по
адресу, а браузер есть на любом аппарате. «Программой» окно делает запуск
Chrome/Edge в режиме `--app` — без вкладок и адресной строки; если такого
браузера нет, откроется обычная вкладка, работать будет так же.

| | |
|---|---|
| `pbreader ui` | сервис и окно (для проверки без основного проекта) |
| `pbreader ui --browser` | то же, но вкладкой обычного браузера |
| `pbreader ui --no-open` | поднять с окном, но не открывать — адрес в stdout |
| `pbreader serve` | **без окна** — режим для основного проекта, по умолчанию |
| `pbreader serve --ui` | окно отдаётся, но не открывается само |
| `pbreader serve --no-ui` | явно без окна |

### Из интерфейса — локальный сервис

```bash
pbreader serve
{"url": "http://127.0.0.1:8756", "token": "…"}
```

Токен печатается в stdout одной строкой — `main.js` читает его при запуске.

```js
const { url, token } = JSON.parse(firstStdoutLine);

// 1. открыли документ
const session = await post(`${url}/sessions`, {
  file: fileUrlOrPath,
  copy_count: 2, is_color: false, is_one_side: false, tray_bin: 257,
});
// → { session_id, sheet_count, sheets: [...], scale: {...}, paper: {margins_mm} }

// 2. показали лист — обычным <img>, токен в адресе
img.src = `${url}/sessions/${session.session_id}/preview/1?side=front&width=900&token=${token}`;

// 3. человек что-то переключил — файл пересылать не надо
await patch(`${url}/sessions/${session.session_id}`, { is_color: true });

// 4. напечатали — и довели до конца
const job = await post(`${url}/sessions/${session.session_id}/print`, {});
// job.status.state: queued → printing → printed | error | cancelled
const done = await poll(`${url}/print-jobs/${job.job_id}`, (s) => s.is_final);
if (done.state !== "printed") showProblem(done.problem);  // «нет бумаги», «замятие»
```

**«Отправлено» — это не «напечатано».** Задание сначала встаёт в очередь, и
только потом из аппарата выходит бумага. Решать по первому событию, брать ли
деньги, нельзя — принтер успеет зажевать лист или остаться без тонера. Поэтому
`/sessions/{id}/print` возвращает `job_id`, а состояние тянется по нему до конца.

Отдельно про `confirmed`. Спулер удаляет запись сразу после того, как задание
отработало, и дальше отвечает одинаково на напечатанное, отменённое и никогда
не существовавшее. Поэтому исчезнувшее задание помечается `state: "printed",
confirmed: false` — «скорее всего вышло, подтверждения не было». Врать в другую
сторону нельзя.

| Метод | Что делает |
|---|---|
| `GET /health` | жив ли сервис (без токена) |
| `GET /print-jobs` | отправленные задания и их состояние |
| `GET /print-jobs/{id}` | состояние одного задания |
| `POST /print-jobs/{id}/cancel` | снять задание с печати |
| `GET /printer-state?printer=…` | готов ли принтер — спросить ДО оплаты |
| `GET /sessions/{id}/coverage` | заполнение страниц и расход тонера на задание |
| `GET /telemetry?printer=…` | что аппарат рассказывает о себе по сети |
| `GET /preflight?printer=…&tray=…` | можно ли принимать оплату прямо сейчас |
| `GET /` | окно программы — только с `--ui` |
| `POST /upload` | принять файл телом запроса (имя — в `X-Filename`) |
| `GET /printers` | принтеры, лотки, возможности |
| `POST /sessions` | открыть документ, получить план листов |
| `GET /sessions/{id}` | описание задания |
| `PATCH /sessions/{id}` | поменять параметры |
| `GET /sessions/{id}/preview/{лист}` | PNG листа (`?side=front\|back&width=900`) |
| `POST /sessions/{id}/print` | печать |
| `DELETE /sessions/{id}` | закрыть |

Вместе с PNG приходит заголовок `X-PbReader-Sheet` — номер страницы, применённый
масштаб, потеряется ли содержимое, предупреждения. Второй запрос ради этого не
нужен.

Сервис слушает **только** `127.0.0.1` и требует токен. Это не формальность: у
него есть метод «напечатать» и метод «открыть файл по пути».

Страница окна получает токен подстановкой при выдаче — и поэтому она
единственная отдаётся **без заголовков CORS**: иначе страница из интернета,
открытая в браузере на этом же компьютере, могла бы её прочитать и забрать
токен. Остальные методы CORS отдают, но без токена они бесполезны.

### Переход с прежнего print.py

Замена лежит в [`integration/print.py`](integration/README.md) — кладётся вместо
старого файла, `main.js` и `config.py` менять не нужно. Протокол тот же: JSON на
stdin, JSON в stdout, код возврата 0 или 1; имя принтера и рабочий каталог
по-прежнему берутся из вашего `config.py`.

Перед переключением поправить надо ровно одно: **лоток теперь число**. Номера
для конкретного аппарата показывает `pbreader printers` — их и прописать в
панели вместо названий вроде `Tray 2`. Подробности и порядок обкатки —
в [`integration/README.md`](integration/README.md).

### Разовая печать — как раньше

Старый протокол PrintBox понимается как есть, фронтенд трогать не нужно:

```bash
echo '{"file_url":"https://…/doc.pdf","copy_count":2,"is_color":false,
       "is_one_side":false,"is_album_orientation":false,"custom_pages":"1-4",
       "tray_bin":"257","device_token":"…"}' | pbreader print --stdin
```

Ключи `is_color` / `is_one_side` / `is_album_orientation` / `copy_count` /
`custom_pages` / `is_all_pages` / `tray_bin` / `device_token` читаются напрямую.
Ответ — JSON в stdout, как и было.

Одно поведение изменилось намеренно: **по умолчанию команда ждёт конца печати**
и возвращает `1`, если задание не напечаталось (нет бумаги, замятие, отмена).
Раньше код возврата означал «спулер принял задание», и на нём нельзя было
строить решение об оплате. Прежнее поведение — `--no-wait`; срок ожидания —
`--wait-timeout` (по умолчанию 300 с). Пароль защищённого PDF — `--password`
или поле `password` в JSON.

### Задание уходит, а бумага чистая

```
pbreader diagnose --test-page
```

Показывает, что драйвер сообщает о выводе растра, и печатает пробную страницу
**мимо PDF** — картинку, нарисованную прямо в коде. Это разделяет две беды,
которые снаружи выглядят одинаково:

* лист с рамкой и полосами вышел → путь до бумаги рабочий, дело в документе;
* лист чистый → драйвер не принимает наш растр, и в журнале рядом видно, что
  именно он ответил.

## Расход тонера

Аппарат берёт деньги за лист, а тонер тратится за краску на нём. Обычная
страница текста закрашена процентов на пять, сплошной чёрный лист — на сто.
Разница в двадцать раз, и её можно устроить нарочно: принести файл с чёрными
страницами и высадить картридж по цене обычной печати.

Заполнение считается **до оплаты**, по тому, что реально ляжет на бумагу —
после масштаба, поворота и обрезки по области печати. Та же картинка,
уменьшенная вдвое, стоит вчетверо меньше тонера, и это видно в отчёте.

```
GET /sessions/{id}/coverage
{
  "average_percent": 99.9, "maximum_percent": 99.9, "heaviest_page": 1,
  "total_ink_units": 80.0,          // как 80 обычных страниц
  "pages": [{"page": 1, "percent": 99.9, "ink_units": 20.0,
             "channels": {"c": 0, "m": 0, "y": 0, "k": 1.0}}],
  "verdict": {"allowed": false, "violations": ["Заполнение выше 60 % на страницах 1, 2, 3, 4…"]}
}
```

Два числа не совпадают намеренно. **Заполнение** — видимая чернота, то самое
«страница закрашена на 70 %». **Расход** — тонер: сплошной жёлтый лист выглядит
светлым (заполнение 11 %), а жёлтого тонера съедает целую страницу. Для цветной
печати расход раскладывается по красителям, и чёрное считается чёрным тонером,
а не смесью трёх цветных — иначе чёрный лист насчитал бы четырёхкратную цену.

Пороги задаются в настройках и **по умолчанию выключены**:

```json
{ "max_page_coverage": 0.6, "max_ink_units": 40, "enforce_coverage_limit": true }
```

Пока `enforce_coverage_limit` не включён, превышение только показывается —
печать идёт. Так и задумано: у честного документа заполнение тоже бывает под
сотню процентов, фотография закрашена почти целиком. Посмотрите на настоящих
заданиях своего аппарата, где проходит граница, и только потом включайте отказ.
С ним `POST /sessions/{id}/print` отвечает `403` и кодом `coverage_limit` —
**до** отправки задания, потому что после неё тонер уже потрачен.

Насколько это точно: это оценка, соотнесённая с расходом, а не измерение
граммов. Принтер кладёт тонер точками, у него своя нелинейность, и одна и та же
цифра на Canon и на HP обернётся немного разным расходом. Отличить страницу
текста от залитой чёрным она позволяет с огромным запасом — для защиты от
такого этого достаточно.

Заполнение **не** защищает от другого злоупотребления — печати сотни обычных
страниц. Против объёма работает счёт листов, он есть в `describe_job`.

## Что знает только сам аппарат

Windows-спулер знает про очередь: он скажет, когда задание из неё ушло. Он **не
знает**, вышла ли бумага, сколько её осталось в лотке и сколько тонера в
картридже. `PagesPrinted` у спулера считает страницы, отданные драйверу, а не
легшие на бумагу — опираться на него нельзя.

Это знает сам аппарат, и у сетевого принтера это можно спросить по SNMP.

**Счётчик механизма** (`prtMarkerLifeCount`) — сколько листов принтер отпечатал
за свою жизнь. Читаем его до задания и после: разница — физическое число вышедших
листов. Именно это убирает «напечатано, но не подтверждено»:

```json
{ "state": "printed", "confirmed": true, "sheets_marked": 2, "expected_sheets": 2 }
```

Если счётчик вырос меньше ожидаемого — деньги взяты, а бумага не вышла, и это
видно, а не теряется. Счётчик догоняет очередь не сразу (задание уходит из неё
раньше, чем последний лист выезжает), поэтому он перечитывается до двух минут.

Оговорка: счётчик общий на аппарат. Если в тот же момент на этот принтер печатал
кто-то ещё, его листы попадут в разницу. Для киоска со своим принтером это не
беда, для общего — повод не доверять числу вслепую.

**Бумага, тонер, неполадки** — то, что надо спрашивать **до оплаты**:

```
pbreader printers
  ...
  по сети (192.168.1.50): HP LaserJet M507dn, s/n PHBCD12345
    отпечатано за всю жизнь: 148253 листов
    состояние: готов
    бумага, Лоток 2: 45 %
    бумага, Обходной лоток: 0 %  ПУСТО
    расходник, Black Cartridge HP 89A: 12 %
```

`GET /preflight` сводит это к одному ответу: `ready`, список причин отказа и
список предупреждений. Замятие, нет бумаги, открыта крышка — отказ. Мало
тонера — предупреждение: печатать ещё можно.

Два правила, из-за которых это не мешает работать:

* **аппарат не ответил — не повод отказать.** SNMP могли выключить в его
  настройках, а печатает он прекрасно. «Не знаю» — это предупреждение;
* **неизвестный уровень бумаги — не пустой лоток.** Многие аппараты не умеют
  считать листы и отвечают «−2». Считать такой лоток пустым значит навсегда
  заблокировать на них печать.

### Если телеметрии нет

Адрес определяется сам: настройки порта во всех мониторах печати, затем имя
порта вида `IP_192.168.1.50`. Оттуда же берётся community, которое Windows уже
настроила для этого порта.

Решение всегда попадает в журнал — молчаливого пропуска нет:

```
Принтер 'HP LaserJet M507': телеметрия с 192.168.1.50 (порт IP_192.168.1.50, community 'public')
Принтер 'HP LaserJet M507': телеметрия недоступна — порт WSD не хранит адрес принтера…
```

Самая частая причина, по которой адрес не находится, — **порт WSD**: Windows
сама находит принтер по сети и заводит такой порт, а адреса в нём нет. Лечится
одним из двух:

* задать адрес в настройках: `"snmp_host": "192.168.1.50"`;
* переустановить принтер на «Стандартный порт TCP/IP» — тогда всё определится
  само, и заодно печать станет предсказуемее.

Проверить адрес, не трогая настройки:

```
pbreader diagnose --snmp-host 192.168.1.50
pbreader printers          # покажет порт и причину, если адреса нет
```

Если аппарат по адресу не отвечает — SNMP выключен в его веб-интерфейсе либо
не совпадает community. Настройки: `snmp_enabled`, `snmp_community`, `snmp_host`.

Клиент SNMP написан свой, без внешних зависимостей: нужен десяток чисел по
известным адресам, а пакеты для SNMP в Python за последние годы несколько раз
меняли имя и владельца — тащить такое в аппарат, который должен работать годами,
плохой размен.

## Устройство

```
job.py        параметры задания (+ старый протокол PrintBox)
geometry.py   лист: физический (всегда книжный) и логический (что видит человек)
layout.py     ← ЯДРО: поворот, масштаб, положение. Чистая арифметика
sheets.py     страницы → листы: дуплекс, копии, чистые обороты
document.py   чтение и растеризация PDF (PDFium)
raster.py     раскладка → пиксели, печать полосами
preview.py    PNG листа: поля, обрезка, предупреждения
printers/     опрос драйвера, сборка DEVMODE (Windows)
output/gdi.py вывод на принтер (Windows)
service.py    локальный HTTP
ui/           окно программы: одна страница, без внешних ссылок
packaging/    сборка в .exe и установщик
integration/  замена прежнего print.py для main.js
coverage.py   заполнение страницы и расход тонера
snmp.py       клиент SNMP v2c без внешних зависимостей
printers/telemetry.py  Printer-MIB: счётчик, бумага, тонер, неполадки
printers/network.py    адрес принтера по его порту в Windows
housekeeping.py уборка рабочего каталога
output/jobs.py  слежение за заданием в очереди печати
output/dib.py   упаковка растра в формат, который принимают драйверы печати
cli.py        команды
```

Два решения, на которых всё держится.

**Лист в принтер всегда идёт книжным.** Альбомность даёт поворот растра, а не
флаг в DEVMODE. Из-за этого флага Canon UFR II и был особым случаем: драйвер
трактовал его по-своему и печатал книжным. Теперь трактовать нечего.

**Область печати спрашивается у драйвера** (`GetDeviceCaps`) и переносится в
логический лист обратным поворотом. Поля у принтера несимметричны — край подачи
шире, — и предпросмотр показывает их там, где они окажутся на бумаге.

## Что проверено

```bash
pytest        # 329 тестов
```

Главный из них — `tests/test_raster.py::TestPreviewMatchesPrint`: собирает
полосы, уходящие в принтер, обратно в лист и сравнивает с предпросмотром.
Для книжной и альбомной, для 1:1 / вписать / заполнить, для страницы с
`/Rotate 90` и для несимметричных полей. Это обещание библиотеки, и оно
проверяется машиной, а не на глаз.

Ветка Windows проверяется на заглушках pywin32 (`tests/win32_stubs.py`) —
разбор ответов драйвера, сборка DEVMODE и то, что непонятое справочное поле не
срывает печать. Заглушки появились после первого запуска на аппарате, где
именно эта, единственная непокрытая тестами, ветка и подвела.

Покрыты также: разбор диапазонов страниц, старый протокол, раскладка по листам,
стыковка полос без щелей, ч/б в предпросмотре, отличие «вылезает за поля» от
«теряется изображение», HTTP-сервис и его токен, подстановка токена в страницу
окна и то, что она не отдаётся кросс-доменно, отрисовка заполненных форм,
пароли, толкование состояний очереди печати, уборка каталога и заполнение
страницы — на эталонных заливках с заранее известным ответом.

## Что ещё НЕ проверено

Всё перечисленное выше проверяется на Linux без принтера. **Ветка вывода на
принтер — `printers/windows.py` и `output/gdi.py` — на живом аппарате ещё не
работала.** Написана она по документации Win32 и повторяет то, что уже делал
прежний `print.py`, но полевых испытаний не заменяет.

Что проверить на Canon LBP722 и HP M507:

1. `pbreader printers` — совпадают ли имена и номера лотков с наклейками;
2. лоток: печать из каждой кассеты, включая обходной;
3. дуплекс по длинной и по короткой стороне; при нечётном числе страниц с
   двумя копиями — не наезжает ли вторая копия на оборот первой;
4. ориентация на Canon: альбомный выходит альбомным (то самое место, где
   ломался прежний путь);
5. поля: `describe_job` показывает `margins_measured: true` и реальные
   миллиметры, а не типовые 4.2;
6. масштаб: A4 → 1:1, A5 → вписан, A3 → вписан;
7. многостраничное задание на 100+ листов — память и скорость;
8. цвет: ч/б на цветном аппарате действительно ч/б.

## Отличия от прежнего print.py

| | было | стало |
|---|---|---|
| Печать | внешний .exe | GDI напрямую, без процессов и окон |
| DEVMODE | `SetPrinter` — глобально, для всей системы | только для своего задания |
| `dmFields` | не выставлялся | выставляется (без него драйвер игнорирует настройки) |
| Лоток | строка руками, на одном пути молча не работала | список от драйвера, нечисловое значение — явная ошибка |
| Поворот | `/Rotate` в копии PDF | поворот растра при выводе |
| Размер страницы | из `/MediaBox` | видимый, с учётом `/Rotate` |
| Предпросмотр | рендер PDF | лист с полями, масштабом, ч/б и обрезкой |
| Скачивание | `verify=False` | проверка TLS (отключается `--insecure`) |
| Office → PDF | процесс мог остаться висеть | закрывается в `finally`; PowerPoint больше не показывает окно |
| Формы | заполненный бланк печатался пустым | `init_forms()` — поля отрисовываются |
| Пароль | документ упирался в тупик | окно спрашивает пароль, API принимает |
| Результат печати | «отправлено в спулер» = успех | задание доводится до конца, ошибка видна |
| Рабочий каталог | не убирался (уборка была закомментирована) | уборка по расписанию, открытые файлы не трогает |
| Проверить настройки | только на киоске, целиком | `pbreader ui` — окно, работает и без принтера |

Прежний путь через SumatraPDF/Foxit не нужен: возможности, ради которых он
держался, теперь есть здесь. Но на время обкатки его разумно оставить рядом —
переключение по одному флагу в `main.js`.
