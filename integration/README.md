# Переход с прежнего print.py

## Как переключиться

1. Поставьте PbReader на аппарат (`packaging/README.md`) или `pip install pbreader`.
2. Замените старый `print.py` файлом отсюда. `config.py` оставьте — из него
   по-прежнему берутся имя принтера и рабочий каталог.
3. `main.js` менять не нужно: протокол тот же — JSON на stdin, JSON в stdout,
   код возврата 0 или 1.

Пути `SUMATRA_PATH` и `FOXIT_PATH` в `config.py` больше ни на что не влияют —
PbReader печатает сам. Удалять их не обязательно.

## Что изменится в поведении

**Лоток теперь число.** Раньше в `tray_bin` писали строку вроде `Tray 2`. Через
SumatraPDF это работало, через Foxit — нет: `DEVMODE.DefaultSource` принимает
только число, строка молча игнорировалась, и лист уезжал в лоток по умолчанию.
Теперь строка даёт явную ошибку. Числа для конкретного аппарата:

```
pbreader printers
```

Их и надо прописать в панели вместо названий. **Это единственное, что нужно
поправить в данных перед переключением.**

**Процесс ждёт конца печати.** Код возврата теперь означает «напечаталось», а не
«спулер принял задание». Если в `main.js` стоит короткий таймаут на процесс,
большое задание в него не уложится — поднимите таймаут либо выставьте
`PBREADER_NO_WAIT=1`.

**Проверяется сертификат при скачивании.** Прежний код ходил с `verify=False`.
Если бэкенд отдаёт документы по самоподписанному сертификату, выставьте
`PBREADER_INSECURE_TLS=1`.

## Порядок обкатки

Прежний путь через SumatraPDF/Foxit можно оставить рядом и переключаться по
одному условию в `main.js`. Разумный порядок на первом аппарате:

1. `pbreader printers` — совпадают ли имена и номера лотков с наклейками;
2. `pbreader ui` — открыть окно, проверить предпросмотр и напечатать пробную
   страницу руками;
3. одно задание через новый `print.py` — из каждого лотка, книжное и альбомное;
4. дуплекс на нечётном числе страниц в двух копиях: не наезжает ли вторая копия
   на оборот первой;
5. и только потом переключать поток.
