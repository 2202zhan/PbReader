# PrintHub

Печать документов через Telegram Web App: человек загружает файл в телеграме,
задаёт параметры, оплачивает — и забирает распечатку у принтера.

Печатью занимается [PbReader](https://github.com/2202zhan/PbReader): он же
рисует предпросмотр на сервере и считает цену. Предпросмотр и печать проходят
через один и тот же расчёт размещения, поэтому картинка на экране показывает то,
что выйдет из принтера, а не то, как выглядит PDF.

## Что уже работает

Фазы 0–4: основание, вход, файлы, параметры с предпросмотром, цена, заказ и оплата.

| | |
|---|---|
| Вход | по подписи телеграма (`initData`), с обменом на собственный токен сессии |
| Файлы | загрузка, список, скачивание, удаление; формат определяется по содержимому |
| Заказ | мастер из трёх шагов: параметры → страницы → проверка |
| Параметры | цвет и стороны на весь заказ; страницы, поворот и копии — по файлу |
| Страницы | отмечаются галочками по миниатюрам, а не строкой «1,3,5-8» |
| Цена | по тарифу из админки, за запечатанную сторону, с надбавкой за заливку |
| Заказ | черновик правится, подтверждённый заморожен вместе с ценой |
| Оплата | счёт в Kaspi, ссылка в приложение, подтверждение вебхуком, возврат |
| Печать | «Я на месте» — задание уходит на аппарат, когда человек рядом |
| Админка | прайс общий и по точкам, точки печати, все заказы, доступ кассы |
| Интерфейс | главная, файлы, заказы, профиль, админка |

Впереди: агент у принтера (фаза 5).

## Про оплату

Счёт выставляется через [kaspi-pos-automation](https://github.com/tapter-dev/kaspi-pos-automation)
— отдельный процесс на Node рядом с нами, наружу он не смотрит. В ответ
приходит ссылка `https://pay.kaspi.kz/pay/…`: она открывает приложение Kaspi
сразу на экране оплаты, и это та самая кнопка «Оплатить через Kaspi».

Три правила, закреплённые тестами:

- **оплату подтверждает платёжная сторона, а не клиент.** «Я оплатил» из
  веб-аппа — это текст с чужого телефона. Заказ становится оплаченным только по
  подписанному вебхуку или по прямому ответу Kaspi на наш запрос;
- **повтор ничего не меняет.** Сервис доставляет подтверждение до трёх раз;
  обработанные события запоминаются, и второй заход не закрывает заказ заново
  и не отправляет второй возврат;
- **сумма сверяется.** Если в подтверждении не та сумма, что в заказе, это не
  оплата и не отказ: платёж помечается расхождением, а разбирается человеком.
  Молча принять меньшие деньги нельзя, молча отказать в принятых — тоже.

Подпись вебхука считается по **сырому телу** запроса, а не по разобранному
JSON: пересборка меняет порядок ключей, подпись перестаёт сходиться, а «починка»
сравнением по разобранным данным открыла бы дорогу подделке. Без
`PRINTHUB_KASPI_WEBHOOK_SECRET` боевой сервер не запускается — иначе
подтверждение об оплате подделает любой, кто знает адрес.

Оплата и печать разнесены намеренно: принтер стоит без присмотра, и лист,
вышедший в лоток, заберёт кто угодно. Платить можно когда удобно, а печать
запускается, когда человек у аппарата.

### Доступ к кассе

kaspi-pos-automation после входа по SMS отдаёт `tokenSN`, `vtokenSecret` и
`profileId`. Они лежат у нас в базе и меняются из админки: перезапускать сервер
ради протухшей сессии никуда не годится. Наружу они не отдаются никогда — только
признак, что заданы.

Сессия живёт ограниченно и продлевается **только новым SMS**, то есть руками.
Когда она кончится, приём оплаты встанет, и отказ об этом скажет прямо — иначе
причину будут искать в коде.

### Платежи понарошку

При `PRINTHUB_DEV_LOGIN=1` вместо Kaspi работает заглушка: «оплата» нажимается
кнопкой, деньги не списываются. Разрабатывать иначе нельзя — каждый прогон
тестов стоил бы реальных тенге, а отказ, просрочку и возврат вообще не вызвать
по желанию. На боевом сервере эта заглушка существовать не может: она привязана
к тому же флагу, что и вход без телеграма, а он роняет запуск в паре с
`PRINTHUB_ENV=prod`.

## Про цену

PbReader цену не знает и знать не должен: он **измеряет** — сколько выйдет
листов, сколько сторон запечатается, сколько тонера уйдёт. Сколько это стоит,
решает тариф, а тариф задаёт админ из панели. В коде цен нет.

Считается за **запечатанную сторону**, а не за лист: двусторонняя печать тратит
вдвое больше тонера при той же бумаге, и счёт «за лист» сделал бы дуплекс
бесплатным. Чистый оборот последнего листа в счёт не попадает — он не
печатается.

Надбавка за сильно залитые страницы — та самая защита от «распечатаю чёрный
квадрат»: факт заливки меряет PbReader, а во сколько он обходится, решаем мы.

Скидка за двустороннюю печать — про бумагу, а не про тонер: её уходит вдвое
меньше. Поэтому скидка даётся только сторонам на листах, занятых с обеих
сторон; последняя нечётная страница едет на отдельном листе и не экономит
ничего. Размер скидки виден прямо на кнопке выбора — это не подарок, а причина
выбрать дуплекс.

Две вещи, которые в коде закреплены тестами:

- **цену, пришедшую от клиента, сервер не принимает.** Веб-апп работает на чужом
  телефоне, его код видно и можно править; сумма всегда пересчитывается на
  сервере из параметров заказа;
- **подтверждённый заказ не пересчитывается.** Админ меняет прайс когда угодно,
  но заказ, который человек уже подтвердил, стоит столько, сколько ему показали.

Администраторы — это номера в телеграме из `PRINTHUB_ADMIN_IDS`. Для всех
остальных админки просто нет: её адреса отвечают 404, а не «нельзя».

## Чего пока нет

- **Заказать можно только PDF.** Word, Excel и PowerPoint загружаются, но
  конвертация живёт на машине у принтера (там Office), а её ещё нет. Заказ на
  такой файл отвечает объяснением, а не пустым листом.
- **Поля печати приблизительные.** Настоящие знает драйвер конкретного принтера.
  Пока его нет, берутся типовые, а в ответе стоит `margins_measured: false` —
  интерфейс обязан это сказать. Агент пришлёт настоящие, и флаг станет `true`
  сам, без правок в интерфейсе.
- **PDF под паролем** отклоняется с объяснением. PbReader пароли умеет, но
  хранить чужой пароль на сервере — отдельное решение, и принимать его молча
  нельзя.

## Устройство

```
Telegram ──► PrintHub Server (FastAPI)
                 ├── PbReader     — предпросмотр и цена
                 ├── SQLite/Postgres
                 └── Kaspi        — отдельный сервис (фаза 4)
                          │
                   мини-ПК у принтера (фаза 5)
```

Сервер на Python не по привычке: PbReader нужно вызывать напрямую, в том же
процессе. Через HTTP к отдельному сервису это тоже возможно, но тогда теряется
единственное, ради чего PbReader писался, — что предпросмотр и печать считает
один и тот же код.

## Запуск на своей машине

Нужны Python 3.10+ и Node 22+.

PrintHub живёт подкаталогом в репозитории PbReader, поэтому сам PbReader —
на уровень выше, и клонировать его отдельно не нужно.

```bash
cd printhub
pip install ..                   # PbReader из соседнего каталога; в PyPI его нет
pip install -e ".[dev]"

cd frontend && npm install && npm run build && cd ..

cp .env.example .env             # заполните PRINTHUB_SECRET_KEY
PRINTHUB_DEV_LOGIN=1 python -m printhub.cli serve
```

Откройте <http://127.0.0.1:8000>. Проверить настройки, ничего не запуская:
`python -m printhub.cli check`.

Фронт можно держать отдельно, с горячей перезагрузкой — тогда два процесса:

```bash
python -m printhub.cli serve          # API на 8000
cd frontend && npm run dev            # интерфейс на 5173, /api идёт в 8000
```

### Вход без телеграма

`PRINTHUB_DEV_LOGIN=1` включает `POST /api/auth/dev` — вход в браузере без
подписи. Иначе разрабатывать можно было бы только с телефона и публичным
HTTPS-туннелем.

Это **вход кому угодно под любым номером**. Вместе с `PRINTHUB_ENV=prod` процесс
не запускается: забыть выключить такое при выкатке — вопрос времени, поэтому
отказ жёсткий, а не предупреждение в журнале.

### Проверка в настоящем телеграме

Телеграм открывает веб-апп только по HTTPS, поэтому локальный адрес нужно
вывести наружу туннелем:

```bash
cloudflared tunnel --url http://localhost:8000     # выдаст https://…trycloudflare.com
```

Затем:

```bash
export PRINTHUB_BOT_TOKEN=...            # из @BotFather
export PRINTHUB_WEBAPP_URL=https://…trycloudflare.com
python -m printhub.cli bot               # настроит кнопку меню и ответит на /start
```

## Про токен бота

Токен — это не только доступ к переписке. Из него выводится ключ, которым
телеграм подписывает данные запуска, и проверка этой подписи — единственное, что
подтверждает личность пользователя. Кто знает токен, тот войдёт под любым
пользователем и прочитает его файлы.

Поэтому: только в переменной окружения, никогда в коде и никогда в git. CI ищет
токены в файлах и валит сборку, если находит. Засветившийся токен отзывается
командой `/revoke` в @BotFather — старый после этого перестаёт работать.

## Тесты

```bash
python -m pytest -q
```

Проверяются прежде всего границы: подделанная подпись, чужой номер в данных
запуска, просроченная строка запуска, чужой файл, файл сверх предела, имя файла
с путём внутри, вход без телеграма на боевом сервере.

```
  telegram/

tests/
```
