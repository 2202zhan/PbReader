# Переход на PbReader: замена print.py

## Нужен ли путь к программе, как SUMATRA_PATH?

**Нет.** SumatraPDF и Foxit — чужие программы: их надо было найти на диске,
развернуть ярлык, поискать в реестре, запустить процессом и надеяться, что они
поймут флаги. PbReader — обычный пакет Python: он ставится в окружение и
импортируется.

**В PyPI его нет** — ставится из исходников. Три способа, по возрастанию
пригодности для парка аппаратов:

```powershell
pip install .                                   # из каталога с репозиторием
pip install git+https://github.com/2202zhan/PbReader.git@<ветка>
pip install pbreader-0.1.0-py3-none-any.whl     # из колеса
```

Для парка правильнее третий: колесо собирается один раз
(`python -m build --wheel`), кладётся в общую папку и ставится на каждый киоск
без git и без доступа к GitHub. Версия при этом одна и та же везде — а это
именно то, чего хочется, когда аппаратов больше одного.

Ставить надо в **тот же Python**, которым `main.js` запускает `print.py`.
Проверить, что попало куда надо:

```powershell
python -c "import pbreader; print(pbreader.__version__, pbreader.__file__)"
```

`SUMATRA_PATH` и `FOXIT_PATH` в `config.py` после этого ни на что не влияют.
Удалять не обязательно.

> `.exe` из `packaging/` — отдельная вещь: окно программы для наладчика
> (`PbReader.exe`). Для `print.py` он не нужен.

## Как переключиться

1. Поставить пакет (см. выше) — в тот же Python, которым `main.js` запускает `print.py`.
2. Сохранить старый: `Rename-Item print.py print_old_sumatra.py`.
3. Положить файл отсюда как `print.py`. `config.py` и `log_rotation.py` оставить.
4. `main.js` не трогать.

Откат — переименованием обратно, в одну команду.

Пробовать, не подменяя боевой файл, можно копией под другим именем: журнал
называется по имени скрипта, поэтому `print_pbreader.py` пишет в
`print_pbreader.log` и `print.log` не засоряет.

Из `config.py` берутся `output_dirs`, `name_printer` и `TARGET_PAPER_SIZE`.
Остальные ключи (`PRINTER_IP`, `printStatus`, `token_db_path`, `input_dirs`) —
не наши, они как были.

## Протокол снаружи — прежний

| | |
|---|---|
| Вход | JSON на stdin, те же ключи |
| stdout | **только журнал**, как и раньше — посторонних строк там нет |
| Журнал | `print.log` рядом со скриптом, ротация через ваш `log_rotation.py` |
| Итог | код возврата 0 или 1 |

Итог задания дополнительно пишется отдельной строкой журнала
`RESULT: {"ok": true, "sheets": 2, "job_id": 7, …}` — её можно разбирать, а
можно не разбирать, ничего не сломается.

## Что нужно поправить в данных до переключения

**Лоток теперь число.** Сейчас в базе `"Tray 2"`. Через SumatraPDF это
работало, через Foxit `DEVMODE.DefaultSource` принимает только число, и строка
молча игнорировалась: лист уезжал в лоток по умолчанию, а узнать об этом было
неоткуда. Теперь строка даёт явную ошибку и код возврата 2. Номера лотков
конкретного аппарата:

```
pbreader printers
```

Это единственное, что нужно поменять в данных.

## Что изменилось в поведении

**Процесс ждёт конца печати.** Код возврата теперь означает «напечаталось», а
не «спулер принял задание»: между этими событиями помещается и замятие, и конец
бумаги. Если в `main.js` короткий таймаут на процесс — поднимите его либо
выставьте `PBREADER_NO_WAIT=1` (срок ожидания — `PBREADER_WAIT_TIMEOUT`, по
умолчанию 300 с).

**Проверяется сертификат при скачивании.** Прежний код ходил с `verify=False`.
Для самоподписанного сертификата — `PBREADER_INSECURE_TLS=1`.

**Формат файла определяется по содержимому.** Раньше файлу без знакомого
расширения приписывалось `.pdf`, и человек получал «Data format error». Теперь
отказ называет вещи своими именами: «Файл «книга.pdf» — это электронная книга
EPUB». Код возврата 2.

**Canon больше не особый случай.** Лист всегда идёт в принтер книжным, а
альбомная ориентация даётся поворотом растра — драйверу нечего трактовать
по-своему. Деления на «Canon и остальные» в коде нет.

## Коды возврата

**Прежние: 0 и 1.** `main.js` не трогаем.

| | |
|---|---|
| 0 | напечаталось |
| 1 | не напечаталось — по любой причине |

Раньше 0 означал «спулер принял задание». Теперь — «бумага вышла»: процесс
дожидается конца печати.

Разделить «не напечаталось» и «задание вообще не приняли» было бы полезно, но
вводить в контракт новое значение вслепую нельзя: если `main.js` проверяет
«код равен 1», любое другое значение сойдёт за успех, и непринятое задание молча
превратится в напечатанное.

Причина всегда есть в журнале, в строке `RESULT`, полем `reason`:

| `reason` | что случилось |
|---|---|
| `bad_request` | задание не приняли: нет файла, не тот формат, лоток строкой, битый JSON |
| `print_failed` | печать не удалась: принтер, замятие, сбой |

Если `main.js` умеет различать коды, включите отдельный:
`PBREADER_EXIT_CODES=extended` — тогда `bad_request` даёт 2.

## Порядок обкатки

Старый `print.py` держите рядом под другим именем и переключайтесь по одному
условию в `main.js`. На первом аппарате:

1. `pbreader printers` — совпадают ли номера лотков с наклейками;
2. `pbreader diagnose --test-page` — доходит ли растр до бумаги;
3. `pbreader ui` — предпросмотр и пробная печать руками;
4. одно задание через новый `print.py`: из каждого лотка, книжное и альбомное;
5. дуплекс на нечётном числе страниц в двух копиях — не наезжает ли вторая
   копия на оборот первой;
6. документ Word и Excel — конвертация через COM на аппарате ещё не проверялась;
7. и только потом переключать поток.

**Canon LBP722 пока не проверялся вовсе** — пункты 1–5 на нём обязательны.
